# ROBOTAC 简明使用说明

## 1. 开始

在项目根目录打开终端，复制执行：

```bash
cd <项目根目录>
ROBOTAC_HEADLESS=0 MIDTERM_RVIZ=1 bash docker.sh start
```

程序会打开 **仿真场景窗口（UeSim）** 和 **地图窗口（RViz）**。场景默认是机器狗第一视角，地图窗口显示扫描结果。**不要重复启动。**

如果之前已经启动且只有地图窗口：先按第 3 步停止，等保存完成后，再执行上面的启动命令。正在运行的隐藏窗口不能仅靠重新设置参数显示。

先原地环视约 40 秒，再自动探索。途中停车约 4 秒是稳定采集；补扫到达后会先对准，再停留最多约 50 秒等待新点云。墙面补扫最多换 3 个观察角度；地面补扫会等待新地图后复查，受总时限控制。

**默认扫描 30 分钟**，随后自动保存和检查。等终端显示最终状态再查看结果。此前 14 分钟专项未通过全部 12 项检查；本次修复后未重新验证 14 分钟，默认仍保持 30 分钟。本次结果只来自本机仿真。

## 2. 看结果

进入下面目录，打开终端显示的本轮编号文件夹：

```text
<项目根目录>/dev_ws/midterm/runs/
```

- `_native.pcd`：原始输出点云；`_preview.png`：预览。
- `地图质量检查.md`：查看墙面、地面、缺口和异常点。
- `result.json`：`COMPLETED` 为通过设定的几何检查；`NEEDS_REVIEW` 为质量不足；`FAILED` 为故障；`CANCELLED` 为主动停止。

本次结构异常修复后，30 分钟通过几何检查的地图编号：`quality_candidate_20261109_visible_30min_06`。14 分钟历史专项及主动停止的诊断测试记录单独保留。

本次另有时序检查：`temporal/temporal_report.json` 记录原始输入，`temporal_filtered/temporal_report.json` 记录入图前测量。可比较墙面 37 处，中心变化复核 0 处、厚度变化复核 0 处；原复核标记保留，另有表面组成复查。仍有 12 处重复支持不足。几何检查和局部时序结果均不能证明全场绝对零漂移，也不代表实物机器人验收。

## 3. 中途停止

另开终端执行，等待部分地图保存：

```bash
bash <项目根目录>/docker.sh stop
```

下次从“开始”重新执行，会重置仿真并使用新编号。主动停止不会标记完成。

## 4. 出现故障

在项目终端执行 `bash docker.sh status` 查看原因。

- GPU 不可用：执行 `bash docker.sh repair`，再执行 `ROBOTAC_HEADLESS=0 MIDTERM_RVIZ=1 bash docker.sh start`。
- 磁盘不足：先留出至少 2GB 空间。
- 位姿跳变、传感器中断、质量未通过：保留本轮日志和质量报告用于排查。

运行期间不要修改源码、配置或强制关闭 Docker。
